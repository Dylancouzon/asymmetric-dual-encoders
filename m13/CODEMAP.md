## Pitfalls carried into M13

1. `corpus_loader.arm_doc_count` scales unique documents with dose; at 200M it asks for 50M documents from a ~6.15M pool. The build needs the registered document-repetition policy, not a bigger draw.
2. `nano10.lr_at`'s default `warmup` is 2,000 STEPS at the screen batch; `trainer10` passes the batch-derived `nano10.warmup_steps_for(batch)` explicitly. Never read the default as the registered value.
3. `bench/core.py:DATASETS` defaults to five datasets; `m7src/_paths` sets six only if imported first. Iterate `partitions.all6`.
4. `pytrec_eval` silently omits a run qid without qrels; assert the scored qid set against the frozen list every time.
5. `m9base` installs `paths_guard`; import the scorer lazily from any training path (pitfall 14).
6. `paths_guard.claim()` verifies the caller IS the module the allowlist entry names, so `score13`
   cannot borrow `m8src.final_run`'s entry. The conditional reserved batch therefore needs its own
   ALLOWLIST entry — a LEDGER 15 amendment — on top of the unpriced encodes (R10).
7. `access13.sh` strips its output; `git status --porcelain` puts a SPACE in column 1, so the drift
   parser uses `sh_raw`. Stripping shifted every parsed path by one character.
8. A frozen payload read from JSON can never carry int qids (keys are strings by construction).
   The int-vs-string hazard is real in `perquery.json`'s qid LIST and in a scored dict, and is
   checked there.
9. `final10.REGISTRY` and `teacher.ENC` are module-level paths; the rehearsal rebinds them from
   `Config` rather than copying either module.
10. A SMOKE must scale EVERY schedule length it derives, not only the dose. The first box smoke of `build13.py` cleared the (since-removed) extension gain bar at 20 steps and started a 2,084,375-step, 30 GPU-hour cycle, because the extension length came from the registered constant while everything else was smoke-scaled.
11. Export runs on the CPU. `nano10.export_onnx` builds its trace inputs on the CPU, so freezing a CUDA-resident model raises "Expected all tensors to be on the same device" — after the build has finished.
12. `trainer10.train_arm(loss_log=...)` TRUNCATES the sidecar it is given on a fresh run, so a resume cannot double-log. Two `train_arm` calls must never share one sidecar file: the second erases the first's history.
13. **Adding a field to a shared artifact is not free.** `corpus_loader`'s assemble manifest is hashed into every checkpoint's recipe fingerprint, so an unconditional `document_policy: null` changed every screen arm's recipe identity without changing its recipe; the same for `epoch_shuffle: false` and for `n_losses` in `trainer10`'s `extra()`. New fields are emitted ONLY when their feature is on, and `test_build13` compares the default key sets against the pre-M13 schema.
14. **`data10.length_buckets` sorts by length and drops the ragged tail**, so the dropped rows are the pool's LONGEST documents and the exclusion is permanent. `EpochShuffledStream` passes `keep_tail=True` because ruling R5 registers every eligible document once per epoch; the default (screen) path still drops it.
15. **`run_arm.code_identity` does not cover the corpus path.** It hashes `run_arm`/`trainer10`/`nano10` only, so a change to the sampler left an unchanged manifest and a resumable checkpoint. `build13.loader_identity` hashes `corpus_loader.py` and `data10.py` into the build's fingerprint.
16. **LoTTE's qids and pids share one integer space.** `evalkit.run_from_arrays` keeps BEIR's self-hit rule (a doc whose id equals the query's is dropped), so scoring LoTTE with bare ids silently drops query j's positive j. `lotte_gate13` scores under a `q:` namespace and asserts the scored qid set (pitfall 4) every slice.
17. **`paths_guard` allows one `claim()` per process, so a guarded module must claim at RUN time, not at import.** `freeze_lotte` claims at import and therefore cannot be imported beside another claimant; `lotte_gate13.claim_lotte()` runs inside `run()` only when the real tree is read, so the module imports cleanly into the pytest process next to `score13`.
18. **A code identity hashes the tree that RUNS, never a fixture's `cfg.repo`.** The first `lotte_gate13.code_identity(cfg.repo)` looked for the source under the synthetic world and failed every end-to-end test; a fixture that carried copies would have hashed the wrong bytes silently.
19. **DEV-6 for the cloud E arms is deferred, not skipped.** `run_arm.py --dev6 defer` records `dev6: {deferred: true, checkpoint_sha256}` and keeps the record `complete` (E1 needs the COV files, not DEV-6); `dev6_from_checkpoint.py` fills it on the box from the identical `cycle3.pt`. The runner's `code_identity` moved with this flag, as it did for the E-bs32 shape fix; no E arm had a resumable checkpoint.
