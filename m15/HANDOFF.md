## Paper direction and remaining work

The question is what selectable query compute buys while document vectors stay fixed. The main
argument is Constella's three compatible query tiers, exact quality/encoding frontier, and the
extra ANN work required by table queries. One physical binary index illustrates the available
deployment choices; an unquantized configuration nearly consumes Zero's advantage over Nano.
The fixed-code query-precision control adds a fourth main figure: keeping query magnitudes restores candidate information without changing the encoder or document sign codes. It is not a native ANN or latency result. Teacher/table choice and component build costs support construction decisions. Routing headroom
and weak actual policies receive a short main-body summary; their details, blending, prefixes,
and shuffle/dimension diagnostics stay in appendices. The goal is useful research and community
credibility, not product promotion. Prior art limits priority, not explaining the capability.

E15 adds the concrete teacher-choice consequence and task sensitivity, narrows the size claim,
and prices Nano's recorded training time. $95 is the training loop at a historical rental rate,
not complete project cost. Zero's 20-minute / 8-12-hour figures are ledger estimates. The screen
still predicts only closed-form tables, not the served Zero or Nano recipes.

## Mac pitfalls learned this milestone

- One MPS job at a time; an MPS encode hung for six hours in a Metal wait (process state `UN`). Watch
  shard timestamps, not only the log. Identify Mac jobs by pid and start time: `ps` truncates the
  command line, which once made a live job look dead and caused a duplicate run.
- Latency runs need an idle machine; background load moved FiQA encode latencies by up to 1.7x.
- `pgrep -f` over SSH matches its own command line; use a bracket pattern (`[e]8x_towers`).
