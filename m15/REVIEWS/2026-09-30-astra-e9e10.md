1. **P1 — Reproduction gate is not enforced.** [m15src/e9_blend.py:31](/Users/dylanc/Documents/GitHub/asymetric-dual-encoders/m15src/e9_blend.py:31), [m15src/encode_more.py:22](/Users/dylanc/Documents/GitHub/asymetric-dual-encoders/m15src/encode_more.py:22). E9 scores whatever `doc_vectors()` returns without checking a gate. The preparation script records failures but continues, and E10 checks agreement only for its dev caches. Consequently, failed evaluation vectors can enter both results despite the registration requiring gated vectors. **Minimal fix:** require a passing gate for the vectors and encoder paths actually used, and stop the affected dataset on failure before producing scores or caches.

2. **P1 — E10’s margin includes documents excluded from its retrieval results.** [m15src/e9_blend.py:42](/Users/dylanc/Documents/GitHub/asymetric-dual-encoders/m15src/e9_blend.py:42). The margin uses raw `topk_arrays()` scores, whereas the evaluated search removes documents whose ID equals the query ID (`m7src/evalkit.py:50–55`). Whenever a self-hit occupies the top ten, f4 measures a different retrieval list; this can change its fitted direction, thresholds, and routing decisions. **Minimal fix:** retrieve sufficient candidates, apply the same self-hit exclusion, then take the first and tenth surviving scores.

3. **P2 — E9 omits the registered macro bootstrap intervals.** [m15src/e9_blend.py:93](/Users/dylanc/Documents/GitHub/asymetric-dual-encoders/m15src/e9_blend.py:93). Registration lines 307–309 require paired intervals for each dataset and the six-set and clean-four macros. Only dataset intervals are produced. **Minimal fix:** independently resample paired query differences within each dataset, average the dataset means with equal weight on every draw, and emit both macro intervals.

4. **P2 — E10 omits the registered post-retrieval routing cost.** [m15src/e10_router.py:96](/Users/dylanc/Documents/GitHub/asymetric-dual-encoders/m15src/e10_router.py:96). The output declares completion without computing the E1/E2 cost required by registration lines 335–336. This matters because f4 always pays for Zero’s search and additionally pays for Nano’s path on routed queries. **Minimal fix:** report that cost at each realized routing fraction using E1/E2 inputs, or explicitly leave the cost component incomplete until those inputs exist.

A stronger experiment these results enable is a dev-frozen, budget-matched cascade comparing Nano-only escalation with escalation to the E9 blend, including both searches in the cost. It would test whether Zero’s signal remains useful after deciding to spend more query compute, using the same encoders, index, and largely reusable computations.
