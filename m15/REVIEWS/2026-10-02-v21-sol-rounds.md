## Proposed thesis (broad, one idea)

The document index is a durable, expensive asset; the query encoder is a recurring cost that can be chosen separately from it. The paper asks what that separation gives and what it costs, along three axes that each change a production decision:
- Quality: what the existing index decides about how good a cheap query encoder can get (strongest original encoder, weakest table student; dimensionality; cheap to test by fitting and measuring in minutes; vector fidelity does not predict retrieval).
- Search cost: cheap query vectors make the unchanged graph work harder (about two to four times the ef; recurs over 25 spaces and in LightRetriever's jointly trained lookup path; the original queries' distance ratio flags susceptible workloads). The engine sets ef per request, so the remedy is a per-path search setting, not a rebuild.
- Flexibility and construction: one index serves a family of query budgets chosen per request (Stella, Nano, Zero), each with measured quality, encoding time, search setting, and one-time construction cost that can be amortized over recurring savings. Over the same index, lexical fusion, query precision under binary quantization, and per-query routing change the trade-off; automatic per-query routing by simple query features failed, while choosing by request context needs no predictor.
