[~1.5 min] [Trace the timeline from the corpus job to a new request.] I built the index for tonight's demo on my desktop. The estimate on screen comes from the stretch where the machine behaved itself. In real time it took six and a half hours, including a memory spill and a crash. That's the job I'd have to schedule again if I changed how I represent the passages. A query has a different deadline. Someone's already waiting for the results when the model starts. On a cache miss, I have to make a fresh vector before the search engine can even start looking for neighbors. If the user is an agent that calls search several times to answer one question, I pay that cost on each uncached call. That's what made the query encoder worth pulling out and testing on its own. Even a modest saving adds up when the same service handles query after query. So I started with the expensive thing I'd already built. Could I teach a smaller model to ask it questions?
