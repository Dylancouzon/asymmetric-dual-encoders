Live: A Traffic Spike on One Index

LIVE

2.68M passages, one Stella index, real NQ traffic, judged answers, on this laptop.

[~4 min] [Before the talk: start the demo server, set the budget to 100 ms, clear the scoreboard with U, and run every mode once to warm it. Keys: 1 Stella, 2 Nano, 3 Zero, 4 Zero narrow, 5 Auto, S spike to 1,000 or back to 40, T replay the same traffic for 12 seconds and add a scoreboard row, arrows step the traffic. Wait for each row before the next key. Press the up arrow once, wait for 1,500, then press it again for 2,000.] [Share the demo. Press 1.] This is a search service on this laptop: the 2.68 million passages, one Stella index, real NQ questions arriving, and every answer checked against the judged answers. The big number asks one question: did the person get a relevant result in the top 10 within 100 milliseconds? [Press S, then T.] Traffic just went up 25 times. Stella still ranks well when it finishes, but almost nobody gets an answer in time. [After the row appears: press S, then C. Talk for 15 seconds while the laptop cools.] Back to quiet traffic. The usual fix is a bigger machine or a second, cheaper index. I'm going to change only the query encoder. [Press 2, S, then T.] Same index, same replayed traffic. Nano keeps up. [Press the up arrow twice to 2,000, then T.] Double it again and Nano falls behind too. [Press 3, then T.] Zero should win this, it has no transformer. It doesn't, because its wide search is now the bottleneck. [Press 4, then T.] Same lookup table, narrower search: most answers come back in time again, and you can see what that costs in ranking quality. [Press 5, then sweep: down to 40, S to 1,000, up twice to 2,000, then S back to 40.] Now the service picks per request: Stella when it's quiet, mostly Nano under the spike, Nano and narrow Zero at the peak, and back to Stella when traffic falls. One index the whole time. [Return to the deck.] On another machine the crossover points move. That's why you measure it on yours.
