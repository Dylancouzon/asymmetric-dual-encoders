[~1.75 min] Suppose I want to go from Paris to Rome. If I reverse those cities, I'd like a different ticket. Zero gets the same bag of tokens either way. I look up the same rows with the same weights. Both queries produce exactly the same vector. I wanted to see how much a contextual encoder would gain here. I wrote 24 pairs of queries where reversing the direction changes the answer. I gave each pair two passages, one intended for each direction. I counted a pair as a success only if the right passage came first on both queries. Stella changed its vector on every reversal. [click] Stella ranked the right passage first in both directions on 4 of 24 pairs. All four successes were unit conversions. That's a small exploratory test. The query and passage pairs are in the repository. For Zero, this kind of reversal disappears during pooling. For Stella, a change in the query vector was easy to measure. Getting both rankings right was harder. Nano gives me a way to keep a contextual encoder on the query side at a smaller cost.
