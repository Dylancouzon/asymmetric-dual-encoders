What a Lookup Table Cannot See

Zero: Stella's WordPiece tokenizer (30,522 tokens), one learned row per token, √count-weighted mean, then L2. Token splits shown are the real tokenizer output. On 24 query pairs where direction changes the answer, Zero ranked the right passage first in both directions for 0 pairs, Stella 4, Nano 2 (results/m15_talk_word_order.json). Exploratory.

[~2 min] [Point to the three headings.] Zero is fast because it skips the transformer. Here is what that costs. Zero does three things: it splits the query into tokens, looks up one row per token, and averages the rows. [Order.] An average has no order. Paris to Rome and Rome to Paris have the same tokens, so Zero builds exactly the same vector and returns the same list. I tested 24 pairs where direction changes the answer. Zero got none of them right in both directions. Stella got four, so this is hard for everyone, but Zero cannot win one. [Context.] Each token has one row, whatever sits next to it. Bank in river bank and bank in bank loan is the same row. A transformer mixes tokens with attention, so its bank depends on its neighbours. Zero only has the other rows in the average to separate the two. [New words.] The vocabulary is fixed at 30,522 pieces. A word it has never seen, like qdrant, splits into pieces whose rows were learned from other words. A transformer can put those pieces back together; Zero averages them. So Zero works best on short keyword-like queries, and I'd test longer, phrased questions separately.
