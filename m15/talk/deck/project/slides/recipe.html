The Monday Recipe

01

Sample real queries

with relevance judgments, from your traffic

02

Measure exact nDCG@10

for each candidate encoder, on your index

03

Sweep hnsw_ef

and oversampling, per encoder

04

Pick the cheapest setting

that meets your relevance floor and p95

[~2.0 min] I'd start Monday by sampling queries from my own traffic and getting relevance judgments. I'd choose a minimum nDCG@10 and a p95 latency budget before I pick an encoder. The benchmark averages tell me which changes are worth a look. Those two limits tell me if I can ship one. I'd run exact search for each candidate over the document vectors I have in production. If an encoder already falls below my relevance floor there, I can see the ranking problem before I add the graph. Then I'd sweep hnsw_ef for each encoder. On a quantized index I'd sweep oversampling too, so I can see what I gain by rescoring a larger group of candidates. I'd measure nDCG@10 again at the settings I can serve. Finally, I'd time completed requests, from text in to results out. I'd record p95 with encoding and search in the same request on the system I plan to use. Then I'd pick the cheapest encoder and search settings that clear both limits. If I serve more than one budget, I'd carry the search settings with the encoder choice. The index can serve each of them.
