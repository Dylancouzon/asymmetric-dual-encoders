[Draft notes; Sol pass pending.] Here is the whole method as one optimization. Choose the encoder e, the search breadth ef and the oversampling os that minimize median request time, subject to a relevance floor and a p95 budget that you set before you look. To fill it in: sample and judge real queries; measure each encoder with exact search on your own index, so the graph doesn't hide encoder quality; sweep ef and oversampling for each encoder separately, timing encoding and search together; then pick the cheapest point that clears both constraints. If you serve several budgets, the search settings travel with the encoder choice. The index stays the same.
