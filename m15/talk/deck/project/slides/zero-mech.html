[~1.5 min] [Follow the highlighted rows from the tokens to the output.] Take "cheap flights Paris to Rome." Stella's WordPiece tokenizer gives me IDs. Each ID is an address in a 30,522-row table. Each row has 1,024 values, the same width as the document vectors. If I repeat a token, its contribution grows with the square root of the count. The repeat matters a little less each time. I pool a weighted mean and normalize it. If you work with Lucene, think of looking up term weights, except what comes out here is one dense query vector. The stored rows are int8 with one scale per row. The formula shows the scale because the raw integer rows need it to represent the right values. The released NumPy encoder applies those scales at load and keeps fp32 rows in memory. Per query it gathers those rows and pools them. I started the table from Stella's encodings of individual tokens. The desktop RTX 3080 fit the pooled queries to Stella's vectors and matched its scores on paired examples. A second pass trained the table to rank relevant documents ahead of negatives using the frozen document vectors. Follow what survives that pooling step. I get the row and how often it appears.
