# Codex adversarial review of the M10 plan — pass 5 (gpt-5.6-terra, read-only, high effort, 2026-09-01)

Verbatim findings. The reviewer read only the files named in the brief (read-exclusion audited in the full log, which is a gitignored `.log` beside this file). Dispositions: `m10/PLANNING.md` §8.

The three Mac artifacts support their stated probe claims. The planning set is still **not decision-grade**.

- **BLOCKER — COV is already contaminated by design work.** The rank and head probes repeatedly scored CQA programmers/physics, yet those same components are proposed as primary COV selection data. That violates the inherited “no evaluation before its lock” rule. Fix: exclude both CQA components from the COV macro entirely; retain them as disclosed DEV-only diagnostics, and require four untouched, licence-clear COV families.

- **BLOCKER — A3−A2 is not volume-matched.** The exact M9 pool is 463,314 queries; A2 is 4,500,314 with 4.037M PAQ, while A3 is 4,463,314 with 1M PAQ + 3M synthetic. Re-screening can further diverge them. “Matched volume” and “differs only in data” are false. Fix: lock identical post-dedup/post-decontamination unique counts and hashes for A2/A3 before training.

- **BLOCKER — BRIGHT cannot presently be admitted under the plan’s own licence standard.** The COV record says its third-party documents’ rights are not conveyed, but still says “admit.” “Eval-only” is not affirmative commercial evaluation permission. Fix: exclude BRIGHT unless rights to store/process every document are evidenced; replace it with untouched, licence-clear families before enforcing the four-family floor.

- **MAJOR — the selected student is contradictory.** Recipe and status call bge-small/34.5M the architecture; family F makes MiniLM the default unless bge-small wins resolved. The only serving-parity probe is bge-small. Fix: name bge-small explicitly as the screen anchor and MiniLM as the build default, or reverse that ruling; run and lock equivalent MiniLM export/parity before F can select it.

- **MAJOR — generation gate is not executable.** Status specifies 20 queries per form; mandate and planning require 200. The Qwen3-4B fallback has no revision; quantization artifact, decoding parameters, RNG seeds, retry/dedup policy, smoke rubric, acceptance threshold, and accountable reviewer are unset. Fix: use 200/form everywhere and lock all those fields plus one named approver and a bounded prompt-revision rule.

- **MAJOR — the central ledger is missing and underspecified.** Status says `m10/LEDGER.md` does not exist, while the box checklist says to “verify” its structure and the mandate makes it the binding record. Fix: commit a blank ledger schema now, including admission evidence, seed/source IDs, removal tables, exact arm manifests, RNG seeds, COV-macro formula, confirmation calculation, and outcome/action fields.

- **MAJOR — several run rules cannot be reproduced.** Extension cycles do not specify objective/LR or the second-extension trigger; “winner’s margin” in confirmation is undefined; per-step uniform-negative RNG and behavior when a query has no seed document are undefined. Fix: write exact algorithms and seed values into the lock.

- **MAJOR — contamination control misses seed-level leakage and contradicts `forms.py`.** Generated text is screened, but seed passages are not explicitly excluded from protected COV material. Also, prompts prohibit copying five words while the screen catches only 8-grams (or short whole-query containment), and `parse()` deliberately accepts preamble despite the JSON-only contract. Fix: pre-filter every seed against the protected index, reject any five-token copied seed span, and parse only `json.loads(text.strip())`.

- **MINOR — stale history reads as current policy.** `PLANNING §8` still states /6 and /10 multiplicity, three confirmations, a conditional >35M tier, 3–4-week/70–100-hour budgets, and FineWeb approval; current policy is /13, four confirmations, hard 35M, 4–5 weeks/80–110 hours, FineWeb out. Mark every superseded disposition explicitly. Also, STATUS/instructions claim five completed passes while the planning record contains four; add pass 5 only after this disposition is recorded.

- **MINOR — dev-reuse accounting is not fillable.** RESULTS says “~40” CQA scoring passes, while planning describes passes “per basis”; no canonical total or checklist owner exists. Fix: log the exact raw score-read count immediately after each run.

Verdict: not decision-grade yet. The causal A test, untouched selection surface, and affirmative enterprise-grade evaluation rights must be repaired before any screen or data generation; the remaining execution fields should be locked in the new ledger at the same time.
