## BLOCKER

- [m10src/seeds.py:95](/home/dylan/asymetric-dual-encoders/m10src/seeds.py:95) does not screen against the mandated protected index. It calls the legacy `decontam.protected_query_index()`, which covers protected queries only—six/dev/untouched—not admitted COV queries and documents or protected documents generally ([m7src/decontam.py:267](/home/dylan/asymetric-dual-encoders/m7src/decontam.py:267)). Worse, STATUS runs smoke before COV admission, contrary to the mandate that COV join the index before any seed is drawn ([instructions-m10.md:312](/home/dylan/asymetric-dual-encoders/instructions-m10.md:312)). A protected document or later-admitted COV passage can therefore seed generation.

- [m10src/seeds.py:148](/home/dylan/asymetric-dual-encoders/m10src/seeds.py:148) silently trusts any matching cache without re-screening it. The cache key omits store, sampling seed, `screen`, `min_score`, pool size, and—critically—the protected-index version. Seeds cached by step 1 remain accepted after step 2 expands the index. This also bypasses the `ALLOWED_STORES` assertion, so the absolute “cannot leak MS MARCO” property does not hold for cached input.

- [m10src/smoke.py:74](/home/dylan/asymetric-dual-encoders/m10src/smoke.py:74) can print `PASS` from an arbitrary caller-supplied `onform` float. It neither recomputes the rate from `verdicts` nor checks that 50 verdicts exist. Meanwhile [m10src/smoke.py:44](/home/dylan/asymetric-dual-encoders/m10src/smoke.py:44) may produce fewer than 50 samples, and `write_md` never writes the promised per-query verdicts at all. Thus `{"onform": 0.8, "verdicts": []}` can auto-approve a form without the decision-15 evidence.

Five `howto` outputs require at least 125 words but receive 60 tokens ([forms.py:24](/home/dylan/asymetric-dual-encoders/m10src/forms.py:24), [gen.py:31](/home/dylan/asymetric-dual-encoders/m10src/gen.py:31)); five arguments require at least 600 words but receive 400 tokens ([forms.py:30](/home/dylan/asymetric-dual-encoders/m10src/forms.py:30)). Structural JSON can pass, but faithful outputs cannot reliably pass the on-form rubric. The protocol itself needs amendment.

Smoke calls it separately per form, and a scaled driver calling it in chunks will retain duplicates across forms/chunks. The reviewed code therefore does not implement corpus-wide exact deduplication.

- The registered bf16 fallback is not supported. `MODEL` is hard-coded to the AWQ ID at [m10src/gen.py:18](/home/dylan/asymetric-dual-encoders/m10src/gen.py:18), with no model/revision argument. A server exposing `Qwen/Qwen3-8B` will reject the request. `REVISION` is merely printed; neither [health()](/home/dylan/asymetric-dual-encoders/m10src/gen.py:35) nor the request verifies it, so the smoke record can claim a revision that was not served.

- Valid HTTP JSON with malformed `choices` or content crashes outside the retry handler at [m10src/gen.py:64](/home/dylan/asymetric-dual-encoders/m10src/gen.py:64). It neither retries nor drops just that seed, contrary to the one-retry/drop behavior.

- The smoke is biased toward an easier distribution. Topical seeds are the highest keyword scorers from 400,000 candidates ([m10src/seeds.py:116](/home/dylan/asymetric-dual-encoders/m10src/seeds.py:116)), then the judge receives the first 50 outputs ([m10src/smoke.py:44](/home/dylan/asymetric-dual-encoders/m10src/smoke.py:44))—roughly the ten strongest seeds. The file explicitly says the build will not inherit this routing. Therefore the health/finance/howto gate is not measuring the build’s seed distribution.

- The M9 explanation is over-read. The benchmark’s “M9 path” is one corpus, 32 examples and one optimizer step ([rate_bench_real.py:182](/home/dylan/asymetric-dual-encoders/m10src/rate_bench_real.py:182)). Actual M9 steps combine every scheduled source, use their registered per-source counts, normalize over the full mixed step, and step the optimizer once ([m9src/longrun.py:763](/home/dylan/asymetric-dual-encoders/m9src/longrun.py:763)). It also used the simpler M9 model. The 249-vs-226 resemblance shows document padding is a plausible contributor, not that it explains M9.

- `gpu_busy_frac` is not GPU utilization. It is wall time inside the synchronized `step()` bracket ([rate_bench_real.py:139](/home/dylan/asymetric-dual-encoders/m10src/rate_bench_real.py:139)). In prefetch arms, the ending global synchronize can include H2D work enqueued by worker threads for future batches. ## MINOR

- The prefetch queue does shift work outside the timed interval. Up to four already-prepared batches enter the measurement, while up to four produced near the end remain unconsumed ([rate_bench_real.py:210](/home/dylan/asymetric-dual-encoders/m10src/rate_bench_real.py:210)). With 200 steps, worst-case boundary inflation is roughly 2%; it is acceptable as a steady-state estimate but should be disclosed.

- Compile warm-up does not guarantee every shape: 30 randomly drawn batches are used rather than explicitly warming each populated bucket ([rate_bench_real.py:236](/home/dylan/asymetric-dual-encoders/m10src/rate_bench_real.py:236)). A new shape compiling in the timed phase would deflate the rate; global compile caches can conversely favor later corpora.

- The fixed path can silently truncate sequences above 512 at [rate_bench_real.py:108](/home/dylan/asymetric-dual-encoders/m10src/rate_bench_real.py:108). It does not truncate the current M9 corpora because their packer caps at 512 ([m9src/longrun.py:127](/home/dylan/asymetric-dual-encoders/m9src/longrun.py:127)), but this should be an assertion, not `np.minimum`.

- `max_tokens_for()` scales by `floor(n/5)` for non-smoke calls, contrary to the fixed per-request 60/400 contract, and behaves discontinuously for `n=6…9` ([m10src/gen.py:31](/home/dylan/asymetric-dual-encoders/m10src/gen.py:31)). The registered smoke at `n=5` is unaffected.

- Peak memory is `max_memory_allocated`, not total/reserved/device memory. One reported arm is 3.94 GB, so the unqualified “peak ≤3.9 GB” statement is also numerically false ([documents result:63](/home/dylan/asymetric-dual-encoders/results/m10_rate_bench_real_documents.json:63)).

- `query_hits` on long passages is conservative rather than leaky: it rejects on any shared 8-gram, much stricter than the registered 8/32 near-match threshold. `q_whole` correctly detects protected 4–7-word queries embedded inside a passage. This can over-drop and intensify topical selection bias, but it does not under-drop texts covered by the index.

No exception-driven gate was found that automatically returns pass. The important fail-open paths are cached seeds and unvalidated judge scores; other malformed generation or prefetch failures tend to crash or hang instead.

- `query_hits` on long passages is conservative rather than leaky: it rejects on any shared 8-gram, much stricter than the registered 8/32 near-match threshold. `q_whole` correctly detects protected 4–7-word queries embedded inside a passage. This can over-drop and intensify topical selection bias, but it does not under-drop texts covered by the index.

No exception-driven gate was found that automatically returns pass. The important fail-open paths are cached seeds and unvalidated judge scores; other malformed generation or prefetch failures tend to crash or hang instead.
