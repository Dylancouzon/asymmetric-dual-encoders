# Codex (gpt-6-astra, xhigh) design review of m13/STAGE1_DESIGN.md — 2026-09-10, read-only

Brief: the stage 1 design before any code existed. Verbatim output follows.

I would not implement this design verbatim.

1. **P1 — Frozen query text and qrels remain unauthenticated.** The proposed payload checks emphasize lengths, duplicates and qids. But [`verify_and_load:337`](/home/dylan/asymetric-dual-encoders/m7src/final_run.py:337) verifies only the corpus; query-text and qrel authentication lives separately in [`preflight:439`](/home/dylan/asymetric-dual-encoders/m7src/final_run.py:439). Changed query text with identical qids can pass the proposed checks. **Fix:** move the complete qid/query-text/qrel hash verification into a per-dataset loader inside the transaction, checking the exact objects subsequently scored. R1’s relocation is sound; relocating only alignment checks is insufficient.

2. **P1 — `verify=True` does not mean “frozen caches only.”** [`teacher.py:251`](/home/dylan/asymetric-dual-encoders/m7src/teacher.py:251) derives a cache key and creates its directory; missing shards are encoded at line 291. Defaults include fp16 encoding, and the active teacher defaults to bge-base ([`encoders.py:11`](/home/dylan/asymetric-dual-encoders/m7src/encoders.py:11)). A stale environment can therefore pass the directory-glob preflight and start another encode after spending access. **Fix:** pin Stella’s complete encoder specification, revision, dtype and exact cache identity; require existing authenticated shards and prohibit encoding fallback. Persist the consumed cache provenance. Claim 5 needs these qualifications.

3. **P1 — Recovery lacks the required durable identity and attempt state.** [`EXECUTION.md:10`](/home/dylan/asymetric-dual-encoders/m13/EXECUTION.md:10) explicitly requires an authenticated empty manifest. The design’s first identity-bearing write arrives with scores. It also omits durable attempt counts despite [`final_run_registry.json:161`](/home/dylan/asymetric-dual-encoders/m10/final_run_registry.json:161) limiting continuation attempts. **Fix:** persist a BEGIN-bound empty manifest before tagging, binding checkpoint/system, code/config, registry and expected outputs; record attempts before reads. Validate both continuation and recovery against it, including dirty-file drift and the remote tag target. Persist bridge success/failure too: raw scores alone must never let recovery bypass a failed bridge.

4. **P1 — The inherited guard does not seal the six, and M9 cannot inherit M10 continuation.** [`paths_guard.py:95`](/home/dylan/asymetric-dual-encoders/m8src/paths_guard.py:95) classifies only `untouched-*` under frozen evaluation; its allowlist has no M13 executor. Merely installing it leaves six-set recovery reads possible and reserved execution unauthorized. Separately, [`final9.py:17`](/home/dylan/asymetric-dual-encoders/m9src/final9.py:17) forbids post-tag rereading; M10’s continuation amendment does not amend M9. **Fix:** implement reviewed, phase-specific access enforcement, keep M9 six-only, and either retain M9’s crash policy or obtain its own dated amendment.

5. **P1 — Fresh extension calls change the training trajectory.** [`trainer10.py:88`](/home/dylan/asymetric-dual-encoders/m10src/trainer10.py:88) exposes neither `warmup` nor an extension handoff. Fresh calls recreate AdamW, reset evaluation history and reseed; line 166 always applies warmup. Ordinary resume instead restores the old step and requires the same fingerprint. Consequently, the proposed `warmup=0`/“extension-aware fingerprint” is not sufficient. **Fix:** add an explicit continuation interface preserving optimizer, RNG and complete midpoint/end history while starting a new local LR cycle. Pure-function checks confirmed that resetting history suppresses a kill that fires with the complete history.

6. **P1 — Global data position requires global mix phase, plus an atomic stop decision.** [`trainer10.py:164`](/home/dylan/asymetric-dual-encoders/m10src/trainer10.py:164) selects Q/D using local steps; [`data10.py:160`](/home/dylan/asymetric-dual-encoders/m10src/data10.py:160) validates that phase. At the second extension, bs32 requires D at local step zero, while the restarted trainer requests Q; bs128 diverges at local step two. Also, retained checkpoints are saved before kill/plateau decisions at trainer line 216. **Fix:** separate global data steps from local schedule steps; reconcile stop decisions before resuming any retained checkpoint. Test the real loader and interruption between checkpoint publication and decision persistence.

7. **P1 — Batch selection has two unresolved execution defects.** Both E arms remain `pending`; [`contrasts.py:170`](/home/dylan/asymetric-dual-encoders/m10src/contrasts.py:170) returns `not_computed` before checking completed outputs. Thus unchanged registry bytes plus the current CLI never produce E1. Furthermore, [`design:26`](/home/dylan/asymetric-dual-encoders/m13/STAGE1_DESIGN.md:26) takes batch from E1, whereas [`instructions-m13.md:15`](/home/dylan/asymetric-dual-encoders/instructions-m13.md:15) permits a LoTTE veto. **Fix:** resolve completion from authenticated arm receipts without editing screen rules; consume the resulting `selected.batch` from screen verdicts, then apply and bind the authoritative LoTTE outcome. A gate file’s mere existence cannot authorize `skipped` or override its veto.

8. **P1 — Claim 3’s loader mechanism is false.** [`is_cut_corpus:868`](/home/dylan/asymetric-dual-encoders/m10src/corpus_loader.py:868) matches source tuples, so a new arm inheriting ANCHOR still receives cut A4. Giving that arm `data: "A4"` instead raises at line 959. Meanwhile, [`assemble_arm:1424`](/home/dylan/asymetric-dual-encoders/m10src/corpus_loader.py:1424) drops the mandatory 12-form requirement for the new name. I reproduced all three behaviors with extracted functions. **Fix:** implement explicit validated corpus/cut/form policies for the build arm; preserve the existing screen path and assert the assembled manifest against the build configuration.

9. **P1 — R5 must ratify specifics, not merely endorse the arithmetic.** Repetition is necessary and consistent with the [archived lock:77]( /home/dylan/asymetric-dual-encoders/research/archive/m10-cleanup-2026-09-10/m10/M102_LOCK.md:77). However, reshuffling each epoch and presenting every eligible document are not specified there. Existing [`data10.py:96`](/home/dylan/asymetric-dual-encoders/m10src/data10.py:96) drops a fixed ragged tail and repeats fixed batches. Full A4 is a plausible intended reading, but the registry records **3,486,034**, not 4M, unique texts ([`screen_registry.json:438`](/home/dylan/asymetric-dual-encoders/m10/screen_registry.json:438)); approximate epoch prose is not a precise sampler contract. **Fix:** obtain R5 before production training, pin eligibility, shuffle, tail handling and cut policy, and describe this as resolving underspecification.

10. **P1 — The cap formula is correct; runtime accounting is underspecified.** The [archived formula:126](/home/dylan/asymetric-dual-encoders/research/archive/m10-cleanup-2026-09-10/m10/M102_LOCK.md:126) is `floor((1000 − mandatory_costs) / extension_cycle_cost)`. But `spent + next_cycle ≤ ceiling` can consume outstanding mandatory reserves after overruns. **Fix:** retain the fixed cap and additionally require `spent + remaining_mandatory_reserve + next_cycle_cost ≤ 1000`; refuse an unaffordable mandatory plan. Include billed idle/setup time, evaluations, encodes, reserved execution, storage and egress. Bind benchmark assumptions and the final batch policy before cycle one.

11. **P2 — Claim 6 is not achievable through path injection alone.** [`final10.canonical:82`](/home/dylan/asymetric-dual-encoders/m10src/final10.py:82) rejects a modified registry copy unless it is the canonical on-disk registry. [`verify_and_load:334`](/home/dylan/asymetric-dual-encoders/m7src/final_run.py:334) still fetches real `BeIR/<all6-name>` corpora. **Fix:** rehearse in an isolated scratch checkout with its own canonical fixture registry, inject the corpus-provider boundary, and deny production data/network access. Keep the actual transaction, hashing, scoring and decision code. Tiny BERT plus fake filenames alone does not establish zero protected access.

12. **P2 — Four unguarded evidence calls can discard valid earlier decisions.** [`final_run_registry.json:185`](/home/dylan/asymetric-dual-encoders/m10/final_run_registry.json:185) explicitly requires independent exception handling. The design’s `evidence_for ×4 → decide` omits it. **Fix:** persist errors separately, omit failed unreachable conjuncts, and use the supported `unscorable` handling for a reached failure. Test C1 rejection followed by an unscorable LEAF comparison.

13. **P2 — Keep the implementation narrower and make remaining packages explicit.** The reserved batch is only an arrow in [`design:76`](/home/dylan/asymetric-dual-encoders/m13/STAGE1_DESIGN.md:76); its three system adapters, registered summaries and recovery need concrete ownership. Cost-frontier work remains separately owed under [`EXECUTION.md:13`](/home/dylan/asymetric-dual-encoders/m13/EXECUTION.md:13). Keep shared scoring helpers and thin M9/nano entrypoints. Drop the blanket five-set-environment refusal: explicit `all6` iteration should work despite that environment. A universal injection framework and a separately registered report-only bridge envelope are unnecessary.
