## B. BLOCKER — code disagrees with the lock

### 1. The amendment has no authority, and STOP is not enforced

The binding mandate still says:

- six arms;
- equal-component tuning-dev macro;
- arm 4 runs after a teacher swap.

V2 instead adds nine runs, family weighting, a seed arm, a batch pilot, and STOP—but labels the amendment as awaiting ratification.

The code only appends a warning at [screen.py:269](/home/dylan/asymetric-dual-encoders/m9src/screen.py:269). `run_arm()` has no STOP check. After a challenger wins, `m9s4` resolves `"selected"` to that challenger and runs. Because `eval9` restricts challengers to SCREEN-3, it produces a SCREEN-3 result despite the registry labelling arm 4 DEV-6.

Concrete fix: obtain an explicit owner-ratified mandate commit. Then implement a persistent state machine: once teacher selection returns a challenger, `run_arm()` must refuse every downstream ID until a new ratified lock supplies the chosen surface/index.

### 2. Equal-token dosing is false

Arm 5 adds the long s2p prefix but still schedules all 16 epochs. Its non-pad dose is therefore substantially greater than 59,507,872.

Arm 6 is deterministically broken:

- Registered query plus realized document tokens are `41,655,510 + 17,852,415 = 59,507,925`, already 53 above the claimed total.
- The rounded per-step budget is `1,960.8 × 30,349 = 59,508,319.2`, another 447.2 above the base.
- Each role fills until `got >= want`, so every step overshoots by up to one whole example.
- A dry stream is not an error. The post-check treats 100% consumption as success.
- Empty batches are skipped at [nano.py:179](/home/dylan/asymetric-dual-encoders/m9src/nano.py:179), while the LR schedule continues to advance.
- Both streams necessarily dry before step 30,349. Consequently the final checkpoint is not recorded, and `rec["history"][-1]` becomes an earlier checkpoint at [screen.py:194](/home/dylan/asymetric-dual-encoders/m9src/screen.py:194).
- If batch 32 wins, arm 6 refuses to build at [screen.py:130](/home/dylan/asymetric-dual-encoders/m9src/screen.py:130).

Concrete fix: build and materialize the complete schedule before locking. Assert, on real token lengths:

- exactly the registered number of nonempty optimizer updates;
- exact total query/document/base tokens;
- each role’s locked final count;
- checkpoint 4 exists;
- no stream exhaustion;
- no empty offsets.

The prompt arm also needs an explicit mandate amendment: either count prompt tokens and reduce presentations, or redefine the dose as content tokens. It cannot simultaneously retain all 16 presentations and have equal actual non-pad tokens.

### 3. The run token does not prevent post-number protocol changes

The token freezes one process interval, not the experiment:

- Tokens live in writable `work/m9tokens` and have no integrity protection.
- A token can be edited or reused for multiple outputs.
- Arms from different commits/fingerprints can be combined; `_load()` checks only an `eligible_for_decision` boolean at [screen.py:213](/home/dylan/asymetric-dual-encoders/m9src/screen.py:213).
- A handwritten artifact can set that boolean.
- `selected()` trusts any existing decision JSON without revalidation at [screen.py:40](/home/dylan/asymetric-dual-encoders/m9src/screen.py:40).
- The decision token is opened after all outcomes are loaded and calculated at [screen.py:313](/home/dylan/asymetric-dual-encoders/m9src/screen.py:313).
- `-smoke` performs no branch, commit, fingerprint or token check and can write any supplied path.
- Checkpoints are written before the guarded result at [screen.py:204](/home/dylan/asymetric-dual-encoders/m9src/screen.py:204).

Concrete fix: create one immutable screen-session manifest before the first pilot. Every arm and the final decision must carry the same session hash, commit and complete fingerprint. At read time, recompute and verify registration rather than trusting a boolean. Make tokens one-use and atomically consumed. Put smoke outputs in a separate namespace that the decision loader cannot address.

### 4. The fingerprint omits material inputs, and recorded code hashes are stale

The fingerprint covers only two data files at [guard9.py:20](/home/dylan/asymetric-dual-encoders/m9src/guard9.py:20). It omits:

- `results/m9_lock_constants.json`;
- teacher target caches;
- document candidate text and vector content;
- banned-row mask;
- dev documents, qrels and query text;
- model/tokenizer/config snapshots;
- `m7src/train.py` and `m7src/mix.py`, which build the training pool;
- dependency wheels/runtime settings.

It also does not compare the starting files with their registered hashes. A modified query pool can be present before `begin_run()` and be blessed as the current fingerprint.

Seven recorded M9 code hashes do not match current committed files: `m9base`, `guard9`, `screen_stats`, `eval9`, `nano`, `screen`, and `port`.

Concrete fix: regenerate the lock constants after the final code change, place their hash in the registry, guard the file itself, and compare every starting input against the registered expected hash. Include all transitive code and data dependencies.

### 5. The fp16 gate does not exist

The lock says fp16 targets are conditional. The implementation always converts incumbent and challenger targets to fp16 at [screen.py:83](/home/dylan/asymetric-dual-encoders/m9src/screen.py:83); challenger caches are always fp16 at [teacher9.py:101](/home/dylan/asymetric-dual-encoders/m9src/teacher9.py:101). There is no 10K sample implementation, no acceptance artifact, and no fp32 fallback.

Concrete fix: implement a guarded preflight producing the locked sample hash and numerical statistics. `query_targets()` must refuse to return fp16 until a matching PASS exists and must have a real fp32 path after failure.

### 6. The mandatory port pilot cannot execute

It has two deterministic failures:

- [port.py:64](/home/dylan/asymetric-dual-encoders/m9src/port.py:64) reads nonexistent `doc_subsample_n` and `doc_subsample_seed`.
- [port.py:190](/home/dylan/asymetric-dual-encoders/m9src/port.py:190) calls `guard9.write_result()` with an unsupported `strict=` argument and never opens a run token.

The `--no-strict` escape hatch therefore survived in a module whose guard no longer supports it.

Concrete fix: use the registered candidate keys, materialize/hash the exact sample, call `begin_run()` before work, remove `--no-strict`, and add an end-to-end test that executes `main()` against a tiny synthetic model/sample.

## MAJOR

### 7. The batch pilot is predictably uninformative

Both pilot arms see the same two epochs, but batch 32 gets four times as many optimizer updates. Each arm also compresses a complete warmup-plus-cosine schedule into its own two-epoch run at [screen.py:64](/home/dylan/asymetric-dual-encoders/m9src/screen.py:64). Neither is the first two epochs of its eventual main schedule.

Given retention of only 0.124 after 2,000 steps, this measures very early optimization speed. It will tend to select “more updates,” not the batch size that wins at final dose.

Concrete fix: either run the batch comparison at the actual candidate doses, or use a token-indexed LR schedule and compare at matched token checkpoints through a preregistered adequacy point. Do not let a two-epoch miniature choose both batch size and final dose.

### 8. `MDE = max(0.0051, 2F)` is not defensible with K=2

`F` is a single absolute difference between two seeds. It is a noisy half-normal draw, not an estimated standard deviation or upper confidence bound. It can be near zero under large real seed variance or arbitrarily inflate the threshold. It measures only the anchor recipe, although seed sensitivity can differ by teacher, student and mix.

Worse, batch selection uses “MDE” before F exists, so code silently substitutes 0.0051 at [screen_stats.py:122](/home/dylan/asymetric-dual-encoders/m9src/screen_stats.py:122).

Concrete fix: either remove the F term and retain the honest artifact-specific scope, or use at least 3–5 anchor seeds and preregister a variance estimator/confidence bound. Do not call a two-seed range a noise floor.

### 9. The teacher screen can select ease of early imitation, not index quality

At this dose the teacher contrast combines:

- teacher-index ceiling;
- target-manifold learnability;
- early convergence;
- low-capacity approximation error.

A stronger index whose query space is harder to imitate may lose at 0.5% of LEAF’s update count and win at final dose—or vice versa. The supplied 0.124 retention observation says the current operating point is far from the teacher surface.

Concrete fix: run the corrected anchor first and preregister an adequacy gate before spending on challenger targets/indexes—for example, require a stable last-two-checkpoint slope and a materially higher retention band. If it fails, increase the pilot dose or declare teacher selection diagnostic rather than launching arms 2–6.

### 10. `screen_stats` is mostly arithmetically correct, but not fully locked

Correct:

- paired within-component bootstrap;
- family-weighted macro;
- Bonferroni teacher quantile;
- teacher contrasts share the same index arrays;
- the larger passing teacher wins and an exact tie keeps stella.

Incorrect or incomplete:

- `align()` uses only the sorted-set hash; `qids_ordered_sha256` is never read.
- The manifest file is not guarded.
- `seed_floor()` performs no manifest alignment.
- `method="linear"` at [screen_stats.py:110](/home/dylan/asymetric-dual-encoders/m9src/screen_stats.py:110) is not registered.
- DEV-6’s 20,000×20,152 integer resamples require roughly 3.2 GB just for index matrices, with large temporary gathers; no RAM budget is registered.
- Arm 6’s missing final checkpoint causes the “last two checkpoints” rule to read checkpoints 2 and 3 instead of 3 and 4.

Concrete fix: bind and verify ordered manifests where order is claimed, validate both seed-floor arms through `align()`, register the quantile estimator, use chunked bootstrap accumulation, and assert required checkpoint step IDs rather than taking `hist[-2:]`.

### 11. Heldout-longq subsetting is only conditionally identical

Subsetting is exactly valid only if the two components have identical:

- ordered document IDs;
- document vectors;
- query bytes/preprocessing for shared qids;
- qrels;
- self-hit policy;
- score tie-breaking.

Code asserts only qid inclusion and qrel equality at [eval9.py:77](/home/dylan/asymetric-dual-encoders/m9src/eval9.py:77).

A separate 55-query encode can also differ slightly because `encode_queries()` uses different dynamic-padding batches. Those tiny bf16 differences can move tied or near-tied documents at the top-10/top-100 boundary. Top-100 truncation itself is harmless for nDCG@10 only if ranking and post-retrieval self-hit removal are identical.

Concrete fix: define heldout-longq formally as a qid subset of the heldout-train transaction, then assert ordered document-ID hash, vector hash, query-text hash, qrels hash, self-hit configuration and tie-break implementation. Cache the full query vectors by qid and subset those exact vectors.

### 12. Arm order and both fallback branches are unenforced

`run_arm()` accepts any registered ID; it does not require pilots, arm 1, or arm 1b to precede later runs. The throughput-over-12-hours fallback exists only in prose/registry. The batch-32 fallback exists in `arm_cfg()`, but makes arm 6 impossible.

Concrete fix: encode the complete allowed-state transition table and refuse any arm whose predecessors, session hash, selected recipe or active dose do not match it.

### 13. The document sample is source-biased

`doc_pool_rows()` sorts the 400,000 randomly selected global row IDs at [data.py:117](/home/dylan/asymetric-dual-encoders/m9src/data.py:117), then arm 6 consumes the first 111,906. That is a low-row prefix, not a uniform sample of 111,906 eligible documents. Its unusually high mean token length—159.5 from the realized count, versus 94.57 for all candidates—is evidence that the prefix changes composition.

Concrete fix: retain RNG draw order, or select the final document set directly using a deterministic token-target sampler and pin its source/length distribution.

### 14. Qwen’s teacher template violates the mandate

The mandate requires the stella s2p template for teacher query targets at [instructions-m9.md:141](/home/dylan/asymetric-dual-encoders/instructions-m9.md:141). The lock/code use Qwen’s repository-specific string at [teacher9.py:45](/home/dylan/asymetric-dual-encoders/m9src/teacher9.py:45).

### 15. Required caches and auxiliary outputs are unguarded

Challenger vector caches reuse any existing correctly shaped chunk without checking its content hash at [teacher9.py:122](/home/dylan/asymetric-dual-encoders/m9src/teacher9.py:122). Concrete fix: content-hash every cache chunk and combined file, stamp registration metadata, and make required ceiling/parity outputs hard prerequisites for teacher decisions.

### 16. Port acceptance does not implement the lock

Even after fixing the crashes:

- the 70 MB target is not applied;
- `pass_all` ignores fastembed;

### 17. The six-hour estimate is not a complete cost model

The quoted 11.72M full-DEV document count is correct: 11,722,963 unique encodes when the shared heldout corpus is counted once. The pair is 48.017 decimal GB fp16. At the quoted Qwen rate, full DEV is 22.381 hours.

But:

- the incremental encode after SCREEN-3 is 11,402,471, not 11.72M;
- no stella-1.5B rate appears in the cited throughput file, so 46.5 hours is unsupported by that artifact;
- 111,906 Qwen documents at 145.5/s take 12.82 minutes, not the ledger’s 26.6 minutes;
- the nine-run formula omits four exact-retrieval evaluations per full arm, port work, fp16 validation, checkpoint I/O and mixed-batch throughput.

Concrete fix: benchmark one complete guarded checkpoint evaluation on DEV-6 and one real mixed training segment, then price the actual execution graph rather than `examples / training ex/s`.

## Will these nine arms produce a usable answer?

No.

- The port preflight crashes.
- Arm 5 is dose-confounded.
- Arm 6 either refuses after a batch-32 selection or silently loses its final optimizer updates and final checkpoint.
- The batch pilot is dominated by early update count.
- The seed-floor arm cannot estimate a floor with K=2.
- Teacher selection occurs where the student is far below the teacher surface, so it is likely to rank early imitability rather than the final asymmetric system.
- Even apparently successful artifacts can be combined across post-outcome lock/code revisions.

The only defensible next GPU action is a corrected, fully guarded anchor curve—not all nine arms. Fix the deterministic blockers, ratify the amendment, freeze one session-wide manifest, and add an adequacy gate before challenger teacher work.
